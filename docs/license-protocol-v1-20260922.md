## 1. 本版改动边界

| 对象 | 本版职责 | 保持的边界 |
| --- | --- | --- |
| 厂商产品证书 | compact JWS，固定 `alg=Ed25519`、`typ=massdb-license+jws`；FE 使用 JDK 17 JCA 验签，厂商工具离线签发 | 私钥不进入 FE、BE、发行包、日志或浏览器；不新增在线证书服务 |
| FE SQL、HTTP、Flight 入口 | 在 FE 接受新的业务读取、正式执行前及返回缓存结果前检查许可；覆盖准备、执行、转发和新计划申请的实际可达路径 | 保留原有账号认证、对象权限和协议；许可检查不替代已有权限 |
| FE `_query_plan` | 在会读取业务数据的规划副作用发生前判断用途，在最终发出新的业务读取计划前确认许可仍有效 | 返回既有格式的计划；不增加要求 BE 验证的新字段、签名或一次性票据 |
| FE 成员管理 | 根据已提交注册清单统计 FE/BE 名额；ADD 受基础额度约束，DROP 实际提交后释放 | 不依赖 BE 续租，不承诺被 DROP 的旧 BE 进程立即失去直连读取能力 |
| FE 证书页面 | 顶部详情 Tab、ADMIN 校验预览与导入、回执查询、有限轮询 | 不在页面或浏览器持久存储证书私钥或完整证书正文 |
| BE 与节点间通信 | 使用既有执行、扫描、取数、维护和认证行为 | 本版不修改 BE 代码、BE 取数接口或 FE↔BE/BE↔BE 协议、端口及连接安全配置 |

不以关闭直连功能、调整网络部署、新增内部鉴权字段或要求升级外部扫描客户端的方式补回 BE 拦截。数据库既有认证、权限及接口开关继续按原规则工作；“不增加许可拦截”不等于扩大既有权限。

## 2. 查询何时检查

| 场景 | FE 的判定点 | 到期后的结果 |
| --- | --- | --- |
| 普通 JDBC/MySQL 新业务读取 | 入口分类及真正开始执行前 | 拒绝新的业务读取 |
| 证书有效时进入 FE 队列，出队时已到期 | 出队后正式执行启动前再次读取当前许可快照 | 拒绝启动；仅入队不构成已执行 |
| 证书有效时已开始执行 | 保存既有查询超时及执行上下文 | 允许在原期限内完成；不因到期主动中断，不借重试延长期限 |
| 预编译或缓存计划再次 EXECUTE | 每次新 EXECUTE 检查当前许可 | 不能以 PREPARE 时间或计划缓存状态绕过 FE 准入 |
| FE SQL 结果缓存命中 | 返回业务缓存结果前检查当前许可 | 新查询拒绝返回业务数据；无需触发 BE |
| FE Flight 新建业务查询或申请新的结果计划 | 对应 FE 准入/执行/发计划入口检查 | 新申请拒绝；已经下发的 BE 结果票据按原行为使用 |
| `_query_plan` 新计划申请 | 规划前处理副作用，发计划前确认当前许可 | 到期后拒绝向客户端发出新的业务读取计划 |
| 客户端持旧计划调用 BE `open_scanner`、`get_next` 或既有结果接口 | 不回到 FE 时没有新增 FE 判定点 | 按 BE 既有行为继续读取或重新创建扫描；这属于本版接受的边界 |

“下一次不能查”精确定义为：**下一次经过 FE 的新业务查询、执行或计划申请在许可无效时被拒绝**，并不表示 BE 将记住计划是否使用过或在到期时废除已下发计划。

例：10:59 FE 在证书有效时下发扫描计划；11:00 证书到期；11:01 客户端继续用这份计划访问 BE，仍由既有数据版本、扫描上下文、权限和超时等条件决定结果。客户端再次向 FE 申请计划时应被拒绝。旧计划可能不止使用一次；本版不承诺其在固定时间内失效。普通 FE 排队查询的“出队再检查”规则不套用到已发给外部客户端的扫描计划上。

## 3. 保留写入、元数据和维护

许可无效、缺失、超额、恢复未就绪或时钟可疑时，新增许可机制只限制相应的新业务读取，不额外停止合法入库、更新、删除、事务提交/回滚、安全元数据及管理修复。

- FE 按语义和真实目标分类，不能简单按 SQL 首词判断；内部目标的 INSERT SELECT、CTAS 等必要读取随合法写入保留。
- 返回业务行、文件导出、面向外部目的地的结果输出，以及表达式向外发送业务值的路径，需要在 FE 可控制的规划或执行入口判断，不能把它们一概归入写入。
- 对需要外部样本或真实业务值的结构推断、统计表达式和 FE 直接 HTTP 读取，先界定用途再调用外部服务，避免拒绝发生在副作用之后。
- 系统维护使用 FE 既有的已验证作业来源与目标事实分类；不新增传给 BE 的维护签名票据，不因自报 `internal` 或用途字符串扩大既有权限。
- Stream Load 等直连 BE 写入继续沿用原机制。BE 直接读文件、binlog、缓存、扫描和结果接口也沿用原机制，其许可拒绝不属于本版承诺。

## 4. 时间、状态与续期

证书使用 UTC 绝对时间，准入满足 `not_before <= now < expires_at`；SQL 会话时区只影响显示/SQL 语义，不改变证书有效期。FE 使用可信时间服务与不可变许可快照；P1 已实现并单测验证本地时钟、提交水位/epoch 核心、离线签名修复和状态评估。真实周期持久化、恢复发布与 FE 准入接入由 P2/P3 完成，不能把内存 Store 测试视为真实集群恢复通过。

产品时间异常不引入内部成员租约，不会因某个新增租约到期而停止写入。时间可疑时 FE 拒绝需要有效读取许可的新申请，保留原账号认证下的合法写入、安全元数据及时间修复。主机完全受控或全盘状态回滚仍不在离线方案的绝对保证范围内。

active、pending 和基础额度来源独立验签与恢复隔离。坏 pending 不使可信 active 失效；坏基础来源关闭新增成员准入，不单独阻断可信查询和写入。pending 生效可影响新的 FE 查询判断，但更高的基础额度必须先提交生效事实才能用于 ADD。防降级序号、部署绑定、历史回执、密钥轮换以及签名时间修复的精确状态转换已由 [P1 核心](/data/project/massdb-sql/docs/license-import-core-20260922.md) 实现并有独立测试；实际提交、重放隔离、成员操作和对外确认由后续适配完成。

## 5. FE/BE 注册名额

名额统计来自 FE 已提交的成员注册清单，不以节点是否在线作为是否占额的条件。现有计划约定的 FE 角色、BE/计算节点计数范围保持不变；并发 ADD 在 Master 上用同一已提交许可/成员事实判断，防止并发超过额度。

DROP 申请、离线或退出进程本身不释放名额；成功提交实际删除后才释放。失败、重试、切主和回放不得重复释放。重新 ADD 是新的成员准入，重新检查当时的可信基础额度。查询证书过期后，可信已生效基础额度继续用于允许的成员管理，不由未验证载荷或坏恢复状态推断额度。

这里的“释放名额”只表示 FE 注册账本释放容量。旧 BE 进程可能仍存活并按既有接口处理旧计划或直接请求；本版没有新的撤权协议、固定撤权时限或旧进程禁用保证。

## 6. 性能约束

许可有效时，FE 热路径只做必要的语义分类摘要复用、不可变状态读取、版本和时间边界比较；不在每条查询上重新解析证书、执行厂商验签、写 journal、发起新增 RPC、获取全局管理锁或扫描全体成员。许可失效不能靠单独后台开关延迟到期边界；轻量检查始终能识别到期和状态版本变化。

管理验签、恢复、成员计数更新和证书页面任务在有界管理路径执行，页面只在需要时加载和有限轮询。FE↔BE/BE↔BE 不新增许可签名、验证、租约、消息绑定或每批检查成本。性能评估仍测量真实端到端 FE/BE 资源；BE 原有指标只作观测，不要求新增 BE 探针或计数器。

[26 项性能用例](/data/project/massdb-sql/docs/license-performance-cases-20260922.json)保留稳定 ID，适用内容收敛到 FE 功能和性能，原内部协议专项明确标记 `out_of_scope`。所有适用用例仍是 `not_run`，不能由“不改 BE”推导性能不受影响；发行前仍需独立 A/A 噪声校准、A/B 对照及真实通过证据。

## 7. 兼容与阶段完成条件

本版不要求 BE、旧计划、外部 scanner、结果客户端增加许可协议；普通 SQL 客户端保留原连接方式。FE 集群须通过发行和升级验证保证所有可能提供查询/转发/计划服务的 FE 均已启用相同准入规则。未升级 FE 的读取边界必须明确，不能把仅部分 FE 生效称为全 FE 入口覆盖；实际升级与恢复步骤仍待实现验证。

旧方案中的节点身份 PKI、节点密钥分发、内部签名范围凭证、成员租约、多数任期证明、32 秒撤权、Java/C++ 内部协议向量及其新增认证开销测试全部移出本版。原 `P0-APPLICATION-AUTH`、`P0-TIME-AVAILABILITY`、`P0-REVOCATION-BOUND` 是该旧方案的未解决问题，当前范围下状态为 `out_of_scope`，不是“问题已实现解决”，也不再阻断本版。

[P0 冻结契约](/data/project/massdb-sql/docs/license-p0-contract-20260922.md)已给出 FE 挂点、用途/副作用顺序、缓存/出队/转发、恢复及混合版本输入，并有部分原版路径可达记录；完整性能基线仍待证明。P1 核心统一100项测试通过，实际断网构建 JAR 的42项互通检查通过，成本记录单列；具体环境与生产信任集交付边界见[实施记录](/data/project/massdb-sql/docs/license-implementation-progress-20260922.md)。随后仍须接入持久化、管理 SQL/API、FE 页面和真实 FE 成员额度，执行集成与完整性能验证，不把核心测试当作这些入口已完成。

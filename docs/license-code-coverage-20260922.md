## 当前交付范围：只在 FE 实施

用户已明确接受旧计划复用风险，并要求不改 BE。本版保留现有连接、端口与通信协议，在 FE 实现证书生命周期、新查询/新计划准入、FE/BE 名额管理和证书页面。BE 执行、扫描、取数、下载、心跳及写入处理保持现状；新增跨节点执行凭证、范围凭证、成员租约、防重放和内部身份体系退出本版。

到期后再次向 FE 请求查询或 `_query_plan` 应受限；到期前已发出的计划仍可能在 BE 重开扫描。Flight 的新 SQL/新计划由 FE 准入，已有 BE `DoGet` 不改。BE 直接 RPC/下载也不能被描述为已由许可封堵。实际 DROP 提交后，FE 释放登记名额，不承诺孤立旧 BE 进程因此即时失能。用户接受这些边界不等于发生概率已经测量，也不证明其不可利用。

原始静态审计的 48 项 C 编号、1,423 条入口/函数注册记录及 1,171 个源码摘要全部保留；原 19 项需求也保留，并新增 R20 记录本轮范围决策。清单不是把旧任务整体留为 `planned`：每条记录都具有当前范围、当前检查位置和当前状态。

## schema v2 的读取规则

- `release_scope` 是当前 FE-only 交付边界；原记录中的 `scope` 仍描述源码/发行可达条件，不能用来判断本版是否实施。
- `historical_hook`、`historical_evidence` 保留原检查建议和静态解释；其中 BE 凭证或通用认证建议属于历史材料，不是当前任务。
- 原 `plan_refs`、`plan_sections` 保留历史 C 项与章节关联。当前任务必须同时读取 `current_plan_refs`、`current_hook` 和 `coverage_item_dispositions`，不能照原检查建议实施。
- `current_release_disposition` 标明完整保留、只保留 FE 部分或由用户接受退出。`current_hook` 是本版逐条实际边界，不会把跨端执行要求隐含地带回。
- `implementation_status` 分别为 `planned_fe_only`、`planned_fe_only_subset` 和 `out_of_scope_user_accepted`。第三种是退出，不能算作通过或已修复；前两种也没有完成证明。
- 空的 `test_ids`、`implementation_commit` 保持真实。已完成的独立证书核心测试另见[实施记录](/data/project/massdb-sql/docs/license-implementation-progress-20260922.md)，不据此给运行入口填入通过结果。
- `source_sha256` 保留1,171个源码/实现摘要，供增量复核；摘要匹配不是代码正确或许可覆盖的证明。SQL 文件候选的 `line: 1` 只是文件锚点，具体委托仍可从历史依据核对。

性能要求适用于实际保留的 FE 工作。正常状态轻量判断、异常状态施加限制；不能把1,423条记录实现为逐请求扫描的规则链。对照测试计入 FE 分类、准入、状态维护、持久化与 UI/API 的真实成本，并观察写入和既有 FE/BE 链路兼容性，不再预设 BE 凭证或新内部身份协议成本。没有真实性能通过记录。

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

Apache Doris is an MPP analytical database. It is a multi-language monorepo:

- **`fe/`** — Frontend daemon (Java, Maven). Query parsing/planning, metadata, coordination. Multi-module Maven build rooted at `fe/pom.xml` with modules `fe-common`, `fe-core`, `be-java-extensions`, `hive-udf`, and `check`.
- **`be/`** — Backend daemon (C++, CMake). Columnar storage engine, vectorized execution, pipeline engine. Source in `be/src/`, unit tests in `be/test/`.
- **`cloud/`** — Cloud-mode meta-service and recycler (C++, CMake). Source in `cloud/src/`, tests in `cloud/test/`. Built only when `--cloud` is passed to `build.sh`.
- **`gensrc/`** — Cross-language code generation. Thrift IDL in `gensrc/thrift/` (FE↔BE RPC, plan nodes, descriptors) and Protobuf in `gensrc/proto/` (internal service, cloud, storage formats). Generated sources feed both FE (Java) and BE/Cloud (C++ via `be/src/gen_cpp`, `cloud/src/gen-cpp`). FE-exposed SQL functions are generated by `gensrc/script/gen_functions.py`.
- **`regression-test/`** — Groovy-based end-to-end SQL regression harness (`framework/`, `suites/`, `data/`, `conf/regression-conf.groovy`). Suites are grouped by the `_pX` suffix (`_p0` default/fast, `_p1`/`_p2` larger).
- **`fe_plugins/`**, **`fs_brokers/`**, **`extension/`**, **`contrib/`** — Ecosystem connectors and plugins (Java).
- **`ui/`** — React/Ant Design admin UI served by FE on port 8030.
- **`thirdparty/`** — Vendored C++ dependency build (`build-thirdparty.sh`). BE/Cloud require these to be built first; `DORIS_THIRDPARTY` env var can point elsewhere.
- **`docker/`** — Dev and release container definitions; `docker/runtime/doris-compose` is the preferred local multi-node harness for regression tests.
- **`pytest/`** — Python integration tests for deploy/load scenarios (separate from regression tests).

## Build

All builds go through **`build.sh`** at the repo root. It sources `env.sh`, which exports `DORIS_HOME`, `DORIS_THIRDPARTY`, `TP_INCLUDE_DIR`, `TP_LIB_DIR`, and selects `MVN_CMD`, Java, and C++ toolchains. Thirdparty libraries must be built/installed under `thirdparty/installed` before building BE or Cloud.

```bash
./build.sh                      # Build FE + BE + broker + be-java-extensions (default ON set)
./build.sh --fe                 # Frontend only
./build.sh --be                 # Backend only (also builds be-java-extensions unless DISABLE_BE_JAVA_EXTENSIONS=ON)
./build.sh --cloud              # Cloud meta-service/recycler
./build.sh --fe --be --clean    # Clean rebuild
./build.sh --be -j 16           # Parallel BE compile
./build.sh --meta-tool          # BE meta tool (requires BE already built)
./build.sh --index-tool         # BE inverted index tool
./build.sh --benchmark          # Google Benchmark binaries in be/
./build.sh --be --coverage      # BE with coverage flags
```

Common env overrides:
- `USE_AVX2=0` — build BE without AVX2 (older x86).
- `ARM_MARCH=armv8-a+crc+simd` — target ARM instruction set.
- `STRIP_DEBUG_INFO=ON` — split debug info into `be/lib/debug_info`.
- `DISABLE_JAVA_CHECK_STYLE=ON` — skip FE checkstyle (speeds up iteration).
- `DISABLE_BE_JAVA_EXTENSIONS=ON` — skip JDBC/Hudi/Java-UDF scanners.
- `DISABLE_BUILD_AZURE=ON` — drop Azure support in BE.

Outputs land in `output/fe`, `output/be`, `output/ms` (cloud), etc. Use `--output PATH` to redirect.

Generated sources: `./generated-source.sh` regenerates Thrift/Proto/function stubs without a full build; `run-fe-ut.sh` invokes it automatically.

## Test

### BE unit tests (GoogleTest)

```bash
./run-be-ut.sh --run                                 # Build and run all BE UTs (ASAN by default)
./run-be-ut.sh --run --filter=FooTest.*              # GTest filter syntax
./run-be-ut.sh --run --filter=-*DeathTest.*          # Exclusion
./run-be-ut.sh --clean --run                         # Clean rebuild then run
./run-be-ut.sh --run --gdb --filter=FooTest.Bar      # Debug single test under gdb
./run-be-ut.sh --run --coverage                      # Emit coverage
```

Test file naming is enforced: files must end in `_test.cpp` and be added to `be/test/CMakeLists.txt`. Output XMLs go to `be/ut_build_ASAN/gtest_output/`. Cloud UTs use `run-cloud-ut.sh` with the same filter conventions.

### FE unit tests (JUnit via Maven)

```bash
./run-fe-ut.sh                                                        # Build + run all FE UTs
./run-fe-ut.sh --run org.apache.doris.utframe.Demo                    # Single class
./run-fe-ut.sh --run org.apache.doris.utframe.Demo#testCreateDbAndTable   # Single method
./run-fe-ut.sh --run A,B                                              # Multiple classes
./run-fe-ut.sh --coverage                                             # JaCoCo report
FE_UT_PARALLEL=4 ./run-fe-ut.sh                                       # Parallel (default 1)
```

The script calls `generated-source.sh` first, so Thrift/Proto changes are picked up automatically. Checkstyle is skipped in UT mode.

### Regression tests (Groovy)

```bash
./run-regression-test.sh                                  # Default group
./run-regression-test.sh --run test_select                # Single suite by name
./run-regression-test.sh --run -g default                 # By group
./run-regression-test.sh --run -d query_p0/sql_functions  # By directory
./run-regression-test.sh --run test_select -genOut        # Generate expected .out
./run-regression-test.sh --run -s test_x -parallel 8
./run-regression-test.sh --clean --run ...                # Wipe output first
./run-regression-test.sh --run -h                         # Full framework flag list
```

Configuration lives in `regression-test/conf/regression-conf.groovy`; logs under `output/regression-test/log`. Docker-mode suites use `docker/runtime/doris-compose` to spin up ephemeral clusters. For local runs, a live FE+BE must be pointed at via the conf file.

### Regression suite conventions (from `regression-test/README.md`)

- Always declare locals with `def` — bare assignments become globals and leak across parallel suites.
- Do **not** set `global` session variables or cluster configs inside a case; if unavoidable, mark the suite `nonConcurrent` and use `set global` only then (otherwise use plain `set`).
- Prefer fixed date literals over `now()` so cases do not rot.
- After `streamLoad { ... }`, issue `sql "sync"` before follow-up queries to stabilize multi-FE runs.
- UDF suites must copy their JAR to every BE.

## Code style and formatting

- **C++ (BE + Cloud)**: `.clang-format` is Google-based with `IndentWidth: 4`, `ColumnLimit: 100`, `AccessModifierOffset: -4`, left pointer alignment. `.clang-tidy` and `.clangd` are configured for LSP usage. Follow the [Backend C++ Coding Specification](https://cwiki.apache.org/confluence/pages/viewpage.action?pageId=240883637) linked from `README.md`. The CI enforces `clang-format` via `.github/workflows/clang-format.yml`.
- **Java (FE)**: Checkstyle runs in the normal Maven build; `DISABLE_JAVA_CHECK_STYLE=ON` bypasses it for speed but CI (`checkstyle.yaml`) will fail. Apache header required on all files (`license-eyes.yml`).
- **Groovy regression suites**: Checkstyle config in `regression-test/framework/checkstyle.xml`.
- **Shell scripts**: `.shellcheckrc` configured; CI runs shellcheck.
- Per-file license header is enforced by `.licenserc.yaml` (Apache RAT excludes in `.rat-excludes`).

## Architecture notes

### FE (Java, `fe/fe-core`)

Two planners coexist. **Nereids** is the modern Cascades-style optimizer under `org.apache.doris.nereids` (parser, analyzer, rules, memo, cost, stats, CBO/RBO/HBO). The legacy planner lives under `org.apache.doris.planner` and `org.apache.doris.analysis`. New SQL features land in Nereids; touching both is only needed for feature parity fixes.

High-value packages:
- `catalog/`, `datasource/` — metadata, internal catalog, external catalogs (Hive/Iceberg/Hudi/JDBC/ES).
- `qe/` — query executor, connection handling, MySQL protocol entry.
- `mysql/` — wire protocol.
- `load/`, `transaction/`, `task/` — ingestion and txn coordination.
- `mtmv/` — materialized views.
- `cloud/` — cloud-mode FE glue to the meta-service.
- `journal/`, `persist/`, `ha/` — BDB JE-based edit log, replay, and Master/Follower/Observer replication.
- `service/`, `rpc/` — Thrift `FrontendService` implementation that BEs and other FEs call.

Metadata is single-writer on the **Master** FE; Followers and Observers replay the journal. When adding new persisted state, bump `FeMetaVersion` and supply a read/write path that preserves backward compatibility.

### BE (C++, `be/src`)

- `vec/` — the vectorized engine (columns, data_types, functions, aggregate_functions, exec, sink, exprs). This is where new expressions, functions, and operators belong.
- `pipeline/` — the pipeline execution engine that schedules vectorized operators.
- `olap/` — columnar storage: rowsets, segment v2, compactions, schema change, delete bitmaps, inverted index.
- `runtime/` — `ExecEnv`, fragment manager, load channels, memory trackers, descriptors, query context.
- `io/` — file-system abstractions (local, HDFS, S3, Azure, cache).
- `service/` — Thrift/BRPC servers exposing `BackendService` and internal RPCs to FE and other BEs.
- `exec/`, `exprs/` — legacy non-vectorized operators; prefer `vec/` for new code.
- `cloud/` — cloud-mode storage client that talks to `cloud/` meta-service.

Generated sources live in `be/src/gen_cpp` (Thrift + Protobuf C++ bindings produced by `gensrc`).

### Cloud (C++, `cloud/src`)

Separate daemon used by the storage-disaggregation deployment. `meta-service/` handles tablet/txn metadata over a FoundationDB-compatible KV (`meta-store/`); `recycler/` reclaims orphaned objects on S3/HDFS; `resource-manager/` and `rate-limiter/` handle cluster-wide policies. FE's `cloud/` package and BE's `cloud/` package are the clients.

### Cross-cutting data flow

A SQL statement arrives at FE over the MySQL protocol → Nereids parses/analyzes/optimizes → a `TPlanFragment` tree (defined in `gensrc/thrift/PlanNodes.thrift` + `Planner.thrift`) is shipped to BEs via `BackendService` → BEs instantiate pipeline tasks from `vec/`/`pipeline/` → results stream back to the coordinating FE. Any change to plan-node or expression shape requires coordinated edits in FE (`nereids/trees/plans`, `planner/`) and BE (`vec/exec`, `exec/`) plus the Thrift IDL.

## PR and CI expectations

- PR template (`.github/PULL_REQUEST_TEMPLATE.md`) requires a test checkbox: regression, unit, or an explicit justification for "no test". Prefer regression tests for user-visible SQL behavior and BE/FE unit tests for internal logic.
- Teamcity is triggered by PR comments; the relevant GitHub Actions (`code-checks.yml`, `checkstyle.yaml`, `clang-format.yml`, `license-eyes.yml`, `be-ut-mac.yml`, `build-extension.yml`, `build-thirdparty.yml`) must be green before merge.
- Commit messages and PR titles follow the pattern enforced by `title-checker.yml` (typically `[type](scope) summary`, see recent `git log`).
